## Intent

**Problem:** Transaction categorisation suggestions generated by the LLM categorisation engine (story 5.3) are persisted in the `suggestion` table, but the `/review` page lacks UI to display them, batch high-confidence (≥ 90%) suggestions into a bulk-accept card, or resolve suggestions via `ledger.setSplitField` with provenance `llm`.

**Approach:** Enrich review items of kind `classify.unclassified` with open suggestion details in `listReviewCards`, implement `acceptSuggestionItem`, `dismissSuggestionItem`, and `bulkAcceptSuggestions` use cases that update splits via `ledger.setSplitField(..., 'llm')` and close suggestion rows, expose HTTP endpoints in `/api/review`, and render individual and bulk-accept cards on `/review` with interactive row unticking and confidence meters.

## Boundaries & Constraints

**Always:**
- Suggestions and their review items are strictly account-scoped (AD-3): partner B never sees suggestions or review items belonging to partner A's private accounts.
- Accepting a suggestion resolves it through `ledger.setSplitField` with `source: 'llm'`. This updates the split's category, sets `categorySource` to `'llm'`, closes the open suggestion as `outcome = 'accepted'`, sets `resolvedAt`, and resolves the `classify.unclassified` review item for that transaction.
- Dismissing an AI suggestion marks the open suggestion as `outcome = 'rejected'` and sets `resolvedAt = now` with an audit record; the underlying transaction split remains unclassified.
- Suggestions with `confidence >= 0.9` are batched into a bulk-accept card at the top of the `/review` page with all items pre-ticked; unticking a row extracts it from the bulk card into an individual suggestion card.
- Suggestions with `confidence < 0.9` (and unticked high-confidence items) render as individual AI suggestion cards displaying the confidence meter and copy ("Very sure · 90%+" or "Fairly sure · X%"), merchant / description, and Accept / Dismiss buttons.
- All new endpoints are declared in `route-manifest.ts` and conform to privacy and route checks.

**Never:**
- Never auto-apply suggestions without explicit user confirmation on `/review`.
- Never expose private transaction details or private suggestions across partner boundaries.
- No new database tables or schema migrations (`suggestion` and `review_item` tables already exist from earlier stories).
- No third-party network calls from client or review routes.

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|----------|--------------|---------------------------|----------------|
| Low/medium confidence suggestion (< 90%) | Transaction with open suggestion at confidence 0.78 | Renders as individual AI suggestion card with "Fairly sure · 78%" and Accept / Dismiss actions | Returns 404 if item already resolved |
| High confidence suggestions (≥ 90%) | 2+ transactions with open suggestions at confidence ≥ 0.90 | Grouped into single BulkAcceptCard ("N more we're very sure about", "Very sure · 90%+") with pre-ticked checkboxes and "Accept all" button | Fails gracefully if any item vanishes |
| Unticking row in bulk-accept | User unticks a row in the bulk-accept card | Unticked row moves out of bulk card and appears below as an individual suggestion card | UI state transition; no backend call |
| Single high-confidence suggestion | Exactly 1 transaction with confidence ≥ 0.90 | Renders cleanly as high-confidence suggestion with "Very sure · 90%+" meter | Handled seamlessly |
| Accept suggestion action | User clicks Accept on card or Accept all in bulk | Calls `setSplitField` with `source: 'llm'`; split category set, suggestion marked `accepted`, review item resolved | Atomic per-split write transaction; 404 if not found |
| Dismiss suggestion action | User clicks Dismiss / Not now | Suggestion marked `rejected` with `resolvedAt`; review item remains open as unclassified transaction | 404 if item not found |
| Private account suggestion | A's private account transaction has open suggestion | Visible only to A; B never sees card, count, or partner chip increment | Enforced by `visibleAccountId` query filtering |
| Stale review item | User accepts/dismisses already resolved item | Returns 404/NotFound | UI refetches and removes card |

## Design Notes

Suggestions with `confidence >= 0.9` are batched by `ReviewPage` into a `BulkAcceptCard`. The component maintains a local `untickedIds` set in state. Items with `confidence >= 0.9` whose IDs are not in `untickedIds` are passed to `BulkAcceptCard`. Any items in `untickedIds`, along with items with `confidence < 0.9`, are rendered in the list as `AiSuggestionCard`s. When "Accept all" is clicked, all currently ticked item IDs are dispatched via `bulkAcceptSuggestions` (or parallel acceptance), updating all splits and closing all suggestion rows atomically.
